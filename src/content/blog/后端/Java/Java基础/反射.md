## 一、什么是反射？

- **概念**：在运行时，动态获取任意类的内部信息（属性、方法、构造器），并动态调用对象方法或修改属性的机制。
- **记忆**：反射就是在运行时“看结构、创建对象、调方法、改属性”。

## 反射核心 API

- **`Class`**：反射的入口，获取类结构。
- **`Field`**：操作成员变量，使用 `setAccessible(true)` 可以访问私有字段。
- **`Method`**：操作成员方法，使用 `invoke()` 动态调用。
- **`Constructor`**：操作构造方法，使用 `newInstance()` 创建对象。

## 代码示例

```java
public class User {
    private String name;

    public User() {
    }

    public void sayHello() {
        System.out.println("Hello, " + name);
    }
}
```

```java
import java.lang.reflect.Constructor;
import java.lang.reflect.Field;
import java.lang.reflect.Method;

public class ReflectionDemo {
    public static void main(String[] args) throws Exception {
        // Class：获取类结构
        Class<User> clazz = User.class;

        // Constructor：创建对象
        Constructor<User> constructor = clazz.getDeclaredConstructor();
        User user = constructor.newInstance();

        // Field：修改私有属性
        Field nameField = clazz.getDeclaredField("name");
        nameField.setAccessible(true);
        nameField.set(user, "Java");

        // Method：调用方法
        Method method = clazz.getDeclaredMethod("sayHello");
        method.invoke(user); // 输出：Hello, Java
    }
}
```

## Class 对象的获取方式

```java
Class<?> clazz1 = User.class;
Class<?> clazz2 = user.getClass();
Class<?> clazz3 = Class.forName("com.example.User");
```

## 二、反射在日常代码和框架中的应用场景有哪些？

反射的应用场景主要分为“主流框架底层应用”和“日常业务手写场景”两大类：

### 一、主流框架底层应用（框架帮你用了反射）

1. **Spring IOC/DI（控制反转/依赖注入）**
   - Spring 容器启动时，通过反射读取配置和注解，调用 `Constructor.newInstance()` 实例化 Bean。
   - 通过反射获取类的私有属性，调用 `setAccessible(true)` 和 `Field.set()` 完成 `@Autowired` 依赖注入。

2. **Spring AOP（面向切面编程）**
   - JDK 动态代理的底层核心就是反射。代理类拦截目标方法后，最终通过 `Method.invoke()` 来调用真实对象的方法。

3. **Spring MVC 参数绑定与注解解析**
   - 将 HTTP 请求中的 JSON 或表单参数，通过反射动态绑定到 Controller 方法的各个参数对象上。
   - 解析 `@RequestMapping`、`@RequestParam` 等注解，建立 URL 到方法的映射关系。

4. **ORM 框架（MyBatis / JPA）与 JSON 工具（Jackson / Fastjson）**
   - **ORM**：将数据库查询返回的 `ResultSet` 结果集，通过反射映射并赋值给 Java 实体类的属性。
   - **JSON**：序列化时通过反射获取对象的 Getter 或属性；反序列化时通过反射创建对象并调用 Setter 赋值。

## 三、获取 Class 对象有哪几种方式？有什么区别？

获取 `Class` 对象主要有 3 种方式：

1. **`Class.forName("全限定类名")`**
   - 最常用。不仅可以获取 `Class` 对象，还会触发类的初始化，执行静态代码块并完成静态变量赋值。
2. **`类名.class`**
   - 在编译时就能确定类的类型。可以获取 `Class` 对象，但不会触发类的初始化，属于延迟加载。
3. **`对象.getClass()`**
   - 只有在运行时才能确定。通过已有的实例对象获取与其对应的 `Class` 对象。

## 四、反射的性能为什么慢？如何优化？

### 1. 性能较慢的原因

- **动态解析**：JVM 无法在编译期间确定要调用的方法，必须在运行时动态查找方法或字段的元数据。
- **安全检查**：反射调用方法时，JVM 需要进行安全检查和权限校验，判断是否具有访问权限。
- **难以内联优化**：JIT（即时编译器）很难对反射调用进行方法内联等底层优化。

### 2. 常用优化方式

- **缓存 `Method` 和 `Field`**：将反射获取到的 `Method` 或 `Field` 对象放入 `ConcurrentHashMap` 缓存，避免重复解析。
- **减少访问检查**：在确认访问安全的前提下调用 `setAccessible(true)`，减少访问权限检查带来的开销。
- **使用 `MethodHandle`**：`MethodHandle` 是 Java 7 引入的调用机制，底层经过优化，性能通常优于传统反射。
- **字节码增强**：运行时使用 CGLIB、ASM 或 Byte Buddy 生成字节码，将反射调用转换为更直接的方法调用。

## 反射的优缺点

- **优点**：灵活，可以在运行时动态创建对象、调用方法和操作属性，常用于框架、配置文件和依赖注入。
- **缺点**：破坏了封装性，代码可读性较差，性能通常低于直接调用，使用时还需要处理异常。
